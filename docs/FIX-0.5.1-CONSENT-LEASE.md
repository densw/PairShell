# 0.5.1 授权等待期间会话提前结束

实际 Mac 日志：`pairing.verified` 在 0 秒，`control.consent` 在 20.84 秒，`session.end` 在 30.98 秒。只检查事件类型与相对时间，未导出客户日志正文。

根因：客户 UI 回调直到用户授权才返回 Gate。等待期间，协调连接虽续订服务端租约，却未续订客户 Gate 的初始 30 秒租约。授权后绑定 Gate 的续订器还要再等 10 秒才首次运行。因此用户在大约第 20 秒后授权，续订可能已晚于初始期限。现有即时授权测试没有覆盖这一人工操作间隔。

修复：

- UI 建立后立即返回待授权 Gate，让 remote 层管理等待状态；在 ACTIVE/PAUSED 前不建立 SSH 执行入口。
- 客户 Gate 从待授权阶段起绑定控制租约，首次续订立即执行，之后仍每 10 秒续订；初始握手续订器交接后停止，避免重复续订。
- 不取消服务端失联 30 秒撤销，也不在重连时自动恢复权限。
- 本机服务关闭时，不再仅显示 WebKit 的 `Load failed`；已结束与连接不明分别说明，其他业务错误保留原错误信息。
- Windows 产物进入独立的版本目录，避免构建覆盖用户正在运行的 0.5.0。

验证：旧代码上两个新回归用例失败；修复后通过。真实等待 35 秒的待授权测试通过，授权前任务检查仍拒绝，授权后建立连接并正常收尾。全量 Go 测试与 vet 通过。Mac 35 秒测试与最终安装包结果按实际运行记录确认。

升级后须关闭旧应用窗口、替换应用、重新创建邀请；旧邀请已领取，不能用于第二次配对。
