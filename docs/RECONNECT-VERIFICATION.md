# 同窗口重新连接验证

2026-11-20 修复商家、客户窗口的会话生命周期。窗口上下文持续到退出，每次连接有独立上下文和递增代次；结束、失败、取消不会永久取消整个窗口。旧回调和旧终端不能覆盖新连接。

客户结束后可返回配对入口并生成新码；等待中的码可刷新。新连接重新核对及授权，不复用旧授权。商家失败后保留输入并恢复重试，终端收到服务端就绪消息后才接收键盘输入；终端单独断开时提供手动重新打开入口，不自动重放命令。

关闭时先关闭 SSH，再取消候选路径。传输层丢弃关闭后的迟到数据和 ACK，避免这些消息提前拆除仍在等待关闭确认的路径。

验证证据：

- `scripts/test-windows.ps1` 全部包通过；固定可执行路径避免重复防火墙提示。
- 最终构建前，`TestDesktopPairCanCompleteTwoFreshSessionsWithoutReopening` 连续三次通过：共六次真实 TLS / PAKE / Pion / SSH 会话，同一个客户和商家窗口对象完成两轮独立授权、命令输出、结束清理及旧授权撤销。
- `TestMerchantRetiresSSHBeforeCancelingCandidatePaths` 连续三次通过；关闭顺序和迟到 ACK 回归均确认修复前失败、修复后通过。
- `node scripts/test-ui-reconnect.cjs` 通过：失败重试、旧 socket 回调隔离、显式终端重开、客户重新生成配对码。
- `go vet ./...`、控制脚本语法检查及五个平台构建通过。
- Windows 安装版原生 WebView2 smoke 通过；真实窗口输入无效码后错误出现在输入下方、输入保留、按钮变为可用的“重新连接”，同窗口再次按 Enter 可提交。

自动化真实连接使用本机测试协调器，不代表已经完成 Windows → Mac 的人工授权终端验收。两台机器的安装及原生验证记录见对应部署文档。
