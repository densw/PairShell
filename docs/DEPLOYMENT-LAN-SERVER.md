# 局域网 Docker 部署记录

部署时间：2026-11-20（Asia/Shanghai）。

- 服务器地址和项目目录由管理员保存在本机部署记录中。
- 启停：在该目录执行 `docker compose up -d` / `docker compose stop`；仅管理 `pairshell-lan` 项目，不改其他容器。
- 协调服务：`https://<LAN-IP>:9443`，显式启用一次性设备码配对；普通客户端不需要部署管理员令牌。
- coturn：<LAN-IP>:3478 UDP/TCP，relay UDP 49160–49200；REST 短期凭据、配额和环回/链路本地/多播拒绝策略。LAN 客户端位于私网，未一概禁止私网 peer 地址。本实例未启用 TURN/TLS，不宣称已测。
- 服务自启：两个容器设置 `restart: unless-stopped`。协调服务使用 scratch 静态镜像；两个服务均使用非 root UID1000、只读根文件系统、cap_drop ALL。
- 上游 coturn 可执行文件的扩展能力与 cap_drop ALL 环境发生启动冲突；派生镜像复制文件内容至无扩展能力的可执行文件，保留原依赖和许可证，不额外授予运行能力。实际中继传输通过后才标记部署成功。

## TLS 与凭据

局域网专用 CA 的私钥仅保留在服务器私有 `certs` 目录；客户端仅保存公开 CA，并将附加信任限制到配置中的精确服务地址。未关闭 TLS 校验，未修改 Windows/Mac 系统全局根证书。

创建令牌、见证令牌与 TURN 共享秘密分别生成，保存在服务器0600的 `.env`，不写入源码和客户端包。用户提供的 SSH 登录密码仅用于交互认证，不保存为文件。

## 实际验证

0.10.1 已在局域网原地升级。两个容器运行正常，coturn 为 4.19.2。升级沿用 TLS 证书和服务凭据，协调容器只挂载服务端证书和私钥。旧镜像与配置备份保存在服务器私有部署目录。新版经专用 CA 验证 HTTPS，并分别通过 TURN/UDP 与 TURN/TCP 验证中继路径可用。设备码、SSH 回环与正常断开同时通过，测试未启动系统 Shell。

- Mac、Windows 的服务 HTTPS 健康检查均通过专用 CA 返回200。
- 通过部署服务真实执行设备码 PAKE，成功交换邀请。
- 强制 relay-only 的 Pion 通道分别通过 TURN/UDP 与 TURN/TCP 传输校验字节；测试没有调用客户系统 Shell。
- 双端原生客户端已分别验证启动、应用图标、配置与后端校验和。

局域网同网段验证不等于跨公网 NAT/CGNAT 打洞验收，未测试的网络不承诺成功。操作测试时仍需客户明确授权。完整操作与风险记录见各平台部署文档及传输说明。
