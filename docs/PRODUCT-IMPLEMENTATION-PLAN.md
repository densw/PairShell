# 终端优先的产品简化实施计划

基于用户 2026-11-19 的实际试用反馈，新的交互要求优先于原设计中复杂的展示流程。

1. 复用开源：先核对 xterm.js、Upterm、tmate、Magic Wormhole/croc 的能力、协议和许可。终端采用 xterm.js + 已有 SSH/PTY；短码通过成熟 PAKE 库交换加密邀请，不让服务器取得端到端邀请秘密。
2. 配置归一：官方服务器内置、设置中允许改自建服务器，CLI 参数 > 环境变量 > 用户设置 > 内置默认。部署凭据不能放进公开客户端。
3. 配对归一：主界面仅保留一次性配对码与连接状态。客户仅在会话建立时批准权限，之后不逐条确认命令。失败码作废，TTL/单次领取/限流维持安全边界。
4. 终端归一：替换商家主界面命令文本框与执行按钮。真正持久 SSH shell 使用 xterm.js，按键、Ctrl+C、Tab、方向键、粘贴、中文和 resize 通过输入字节/PTY resize 转发；不在浏览器解析命令。
5. CLI/MCP：增加直连交互 CLI，默认进入 raw mode，退出恢复本机终端。复用已连接会话的 MCP 引用，CLI/MCP 继续由同一客户授权和审计入口约束。
6. 验证：回归配对/状态机/审计，测试 origin 与 WS 身份认证、持续 shell、多次输入、resize、暂停/结束和日志闭锁；构建跨平台程序。官方服务网络结果与本地模拟测试分别记录。

简化原则：删除重复设置和逐条执行主流程，复用既有传输、授权与审计；不新增账号/设备托管/无人值守，不减弱 TLS/身份认证/撤销。旧 API 保留兼容自动化，不作为交互终端实现。
