# PairShell 三方安全协助

PairShell 把连接和授权分开。协调服务帮助两端找到对方，商家和客户通过自己信任的渠道确认连接对象，客户在本机决定是否开放协助权限。

## 怎样确认对方，以及什么时候允许协助

1. 通过已有的聊天、已知电话号码或当面联系，确认你正在和哪位协助人员或客户沟通。把一次性配对码或邀请链接交给这个人。
2. 连接时，双方在自己的 PairShell 上各看到一个本次校验码。通过独立渠道互相读出完整校验码。两个窗口的完整校验码一致后，商家点击「校验码一致，继续」，客户可以点击「校验码一致，允许协助」。桌面端以点击记录本人确认，身份核验依赖双方实际核对。CLI 仍要求输入对方读出的完整校验码。
3. 双方核对后，客户阅读本机显示的权限并决定是否允许。有疑问、号码不一致或无法通过已知渠道联系到对方时，请结束这次连接。

配对码用于找到本次连接。校验码由双方使用本次密钥和握手信息各自在本机计算，可以用来核对身份。请让对方先读出自己的校验码，也请对方实际核对你读出的值。发送配对码、邀请或同意协助之前，无需向对方提供系统密码。

## 三方各自受到什么保护

| 保护对象 | 代码中的安全边界 | 仍由谁负责 |
| --- | --- | --- |
| 服务器 | 客户端只能访问服务器开放的接口。配对与信令服务对请求大小、速率、并发和房间做限制，私有模式需要部署令牌。TURN 使用有期限的凭据，部署模板限制带宽和中继目的地址。源码可以公开，准入仍由权限检查和私有凭据决定。 | 运营者负责及时更新服务和依赖、保管密钥、限制公网入口和中继出站网络。公开服务暴露于漏洞和流量攻击，功能限额也无法代替上游网络限流。局域网部署应限制在局域网或 VPN 内。 |
| 商家端 | PairShell 的远程执行入口设在客户设备上，会话通过 SSH 绑定本次核验的密钥。内置商家终端会过滤对端发来的剪贴板、显式链接和部分本地终端控制序列，保留常用显示和手动复制粘贴。 | 把对方发来的文本、链接、文件和工具结果作为外部输入。使用独立 SSH 工具附加时，由所用终端保护本机交互。协议解析器、终端组件和本机应用仍需更新和验证。 |
| 客户端 | 会话通过本次密钥认证，执行权限由客户本机授予。客户可以暂停新操作或结束并撤销授权。服务端管理权限和配对码都不能替客户完成本机授权。 | 只授权信任的商家。终端、任务、文件读写与 AI 仍在现有权限范围内，使用当前系统账号能访问的真实路径。若以管理员身份运行，协助也会继承相应权限。本机审计记录和撤销帮助监督，已经发生的操作需要另外检查和处理。 |

## 如果中继运营者或服务器 root 不可信

开启协助的前提仍是两端运行从可信渠道取得的程序、设备和本机授权界面未被控制、会话秘密没有泄露，且双方完成独立渠道核验。满足这些条件时，服务器管理权限本身无法充当任一端的会话私钥，也无法批准客户本机操作。SSH 会话内容由两端加密和认证，经过 TURN 时也保留这层保护。

新版校验码同时依赖握手记录和仅两端持有的随机邀请秘密。服务器即使能查看完整信令，只凭这些数据也算不出校验码。生成配对码的一端独立限制每个码最多三次不同的 PAKE 证明。六位秘密仍可能被猜中，双方独立核验仍是必要步骤。和旧版客户端配对会在核验前终止，双方需同步更新。

服务器仍能观察连接来源、时间和流量规模，也能阻断配对、拒绝续租或关闭中继。请通过已有渠道核对对方从自己设备读取的校验码。

安装包应从可信发布渠道取得。受信任的独立发布密钥可以签署文件摘要清单，用户从独立渠道核验公钥后再校验清单和安装包。分离签名与平台签名分别验证。协议和端点实现仍需独立安全审查，现有自动化验证覆盖具体行为，无法排除未知漏洞。[发布签名流程](release-signing.md) · [协议验收范围](protocol.md#待完成的安全门禁)
