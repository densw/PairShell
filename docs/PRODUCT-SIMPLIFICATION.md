# PairShell 交互简化设计与开源调研

日期：2026-11-19。本文是本轮产品决策与验收要求；实现状态以测试和实际运行结果为准，不能将设计目标视为已验收能力。

## 产品方向

把主要体验从“创建邀请、配置令牌、填写命令、点击执行、刷新结果”改为“分享临时配对码、用户同意一次、直接操作终端”。用户不需要理解房间 ID、SSH 密钥、日志格式、MCP 引用或 TURN；这些由程序处理。CLI 与 MCP 接入同一会话，不另建权限通道。

客户侧最短路径：打开应用 → 分享临时码或输入对方配对码 → 看清本次连接对象并同意 → 查看同一终端，随时暂停/结束。优先让被协助设备展示临时码；为兼容既有发起方式，商家生成码、客户输入也属于同一配对能力。普通用户只看到一种当前流程，不应被迫选择协议或操作角色。

商家侧最短路径：输入配对码或创建本次协助 → 等客户授权 → 焦点进入完整终端。连接建立后不出现逐条命令审批、执行按钮或“命令文本”输入框。方向键、Tab、Ctrl+C、Ctrl+D、组合键、多行粘贴、中文输入与窗口 resize 由终端模拟器和 SSH PTY 承载；不在网页中拆分命令或仿造 Shell 行编辑。

## 开源调研与取舍

| 项目 | 调研发现 | 本项目的采用方式 |
| --- | --- | --- |
| [Upterm](https://github.com/owenthereal/upterm) | Go 终端共享，通过标准 SSH 或 WebSocket 连接，支持独立部署；许可证 Apache-2.0。 | 参考持续交互与连接生命周期，保留现有 Go SSH/PTY 底座。不会把其完整服务器体系再叠加到当前 Pion 架构。 |
| [tmate](https://github.com/tmate-io/tmate) | 基于 tmux 的即时终端共享；README 说明其公共托管入口已停止服务，需自建。 | 参考“一次分享即进入终端”的产品流程，不引入 tmux/C 依赖，也不将其公共服务硬编码为官方入口。 |
| [xterm.js](https://github.com/xtermjs/xterm.js) | 浏览器终端组件，提供 ANSI/交互程序、Unicode/IME 等能力，MIT 许可证。它是模拟器，不是 Shell 或远程执行后端。 | 固定版本并随客户端打包，不依赖 CDN；连接既有 SSH PTY。禁止继续自制 textarea/按钮式终端。 |
| [Magic Wormhole](https://magic-wormhole.readthedocs.io/en/latest/welcome.html) | 使用 PAKE 将人类可输入的一次性短码用于端到端密钥交换，服务器仅中转握手消息。 | 短码设计必须复用经审视的成熟 PAKE 实现。不能简单把长邀请上传服务器再用六位数字查回，也不能将短码哈希当高熵密钥。 |

调研结论：复用成熟终端模拟器、SSH/PTTY 和 PAKE，而不是整体换框架或自研终端/密码算法。已有授权、审计、暂停和撤销检查应保留在客户执行端。

## 信息架构与默认值

- 主界面只保留连接、终端、连接对象/状态和结束入口。日志目录、文件能力、CLI/MCP 接入与服务器设置放入按需展开的位置。
- 默认服务器使用本项目现有部署入口 `https://167.104.165.174:9443`。它是地址配置，不是运行健康或 TLS 有效性的承诺；上线前必须真实检查。连接失败提供重试与编辑服务器入口，绝不静默关闭证书校验。
- 自建服务器在“设置 → 服务器”中编辑并记住。共同配置位于 `os.UserConfigDir()/PairShell/config.json`，只存非秘密偏好；优先级为显式 `--server`、`PAIRSHELL_SERVER`、保存配置、官方默认值。
- 部署创建令牌、TURN 秘密和见证私钥不能随客户端公开分发。自建实例如要求创建凭据，应通过现有受保护凭据机制提供，不能让普通客户填写管理员密码。
- 无人值守、永久设备访问和自动提权不属于此次“简化”。关闭本次协助即撤销权限。

## 安全与交互边界

客户的一次同意明确授权“本次终端协助”，并说明当前系统账号权限与日志录制。AI 接入单独显示其数据发送边界；不把每条命令确认当安全措施。暂停阻止新远程输入，已运行的程序仍可继续；结束先撤销授权，再清理通道和受控进程。

配对码必须短期、单次、受速率限制，失败尝试有明确反馈；身份绑定和私钥证明继续适用。短码用于建立本次可信连接，不是长期设备密码。服务器设置切换只影响下一次连接，不能悄悄把当前会话迁到另一个服务器。

终端内容与远端输出均是不可信数据。终端模拟器允许必要的显示/键盘协议，但不得任由远端 OSC 控制本地剪贴板、打开外部程序或下载执行文件。界面和日志状态不能冒充命令成功或第三方见证。

## 本轮验收

1. 默认无需手填服务器；自建地址可保存，地址验证与 TLS 校验不可绕过。
2. 配对完成、客户一次授权后，至少在同一 Shell 中完成 `cd`、环境变量设置、历史导航、Tab、Ctrl+C 与交互程序，不存在逐条执行按钮。
3. 桌面、原生 CLI、MCP 使用相同会话身份和客户授权；MCP 工具参数不能覆盖目标设备。
4. 暂停/结束立即影响所有入口，重连不自动解除暂停；录制失败拒绝新操作。
5. 短码错误、过期、被重复领取、并发领取与服务器不可达都有测试和可行动错误。
6. 不以交叉编译代替 Windows/macOS 真机键盘、中文 IME、全屏程序、焦点与剪贴板验收。
